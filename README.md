# K剪音

PC 版「音视频转换剪辑工具」（`D:\AiWork\AudioTool`，WinForms + ffmpeg.exe）的安卓版。
剪掉不要的部分、调音量、加淡入淡出，再转成想要的格式；视频可以剪完导出成视频。自用侧载，不联网。

## 功能（0.5.0）

| 功能 | 说明 |
|---|---|
| 外观（0.2.0） | 深色「录音棚」风：墨黑底、薄荷青主色、紫色标淡入淡出；图标是「一刀切开的声波」 |
| 添加文件 | 系统文件选择器多选；也能从文件管理 / 微信「分享」或「用其他应用打开」进来。音频、视频都行；没有声音的视频也能剪（波形是一条平线，0.3.0） |
| 视频画面（0.3.0） | 打开视频时波形上方显示播放头处的一帧，播放时像幻灯片一样刷新；拖选区边线时显示边线处的画面；上一帧 / 下一帧（按视频帧率）；点画面全屏，全屏里能播放、逐帧、标开始 / 结束、加剪辑点 |
| 视频导出（0.3.0） | MP4 (H.264) / MP4 (H.265) / 无损快剪（不重编码，开头对齐关键帧；删了中间或加了效果时自动改 H.264 高画质重编码）；分辨率（只缩不放，竖屏按短边）、画质（CRF 同 PC 版）、保留 / 去掉声音；淡入淡出 = 画面黑场 + 声音渐变。存 `Movies/K剪音` |
| 音视频分离（0.4.0） | 格式选「音视频分离」：一个视频拆成无声视频（`Movies/K剪音`，`xx_无声视频.mp4`）+ 原声音（`Music/K剪音`，`xx_音频.m4a` 之类）两个文件；都不重新编码，按剪辑结果拆，删了中间或加了效果时画面改 H.264 高画质、声音按原格式重编码。纯分离，不是 AI 人声分离 |
| 合并（0.4.0） | 底部「合并成一个」，格式选音频时：列表里全部文件按添加顺序接成一个音频（各自的剪辑和效果都算上），按所选音频格式编码；采样率 / 声道不同会统一（没选采样率用 44100）。视频文件取声音。文件名 `第一个_等N个合并.mp3` |
| 视频合并（0.5.0） | 「合并成一个」格式选视频（H.264 / H.265 / 无损快剪）时：列表里的视频按添加顺序接成一个视频（画面 + 声音，各自的剪辑和效果都算上），存 `Movies/K剪音`，`第一个_等N个合并.mp4`。尺寸照第一个视频（选了分辨率按所选只缩不放），比例不同的保持比例、补黑边居中；帧率统一成第一个的；声音统一 48k 立体声，没声音的视频补等长静音；纯音频文件提示后跳过。无损快剪：都没剪、编码 / 分辨率 / 帧率 / 声音格式都一样时直接拼接不重新编码，否则自动改 H.264 高画质（日志里写原因） |
| 波形 | 单指拖动框选；拖选区两边的圆柄调整；点一下定位播放头；双击选中两个剪辑点之间的整段；双指缩放平移；底部概览条拖动平移 |
| 剪辑 | 剪辑点（播放头处，或选区两端）、删除选区（后面自动接上）、仅保留选区、撤销 / 重做（每个文件各自 200 步） |
| 效果 | 音量 −40 ~ +20 dB（波形变红 = 削波）、淡入、淡出（输入数字，或直接拖波形左右上角的小方块） |
| 试听 | 实时按剪辑结果播放，有选区只放选区；拖音量 / 淡入淡出时立刻能听到 |
| 选区输入 | 开始 / 结束可直接输入 `90`、`1:30`、`00:01:30.5`；「播放头→开始 / 结束」边听边标 |
| 导出 | MP3 / WAV / FLAC / M4A / OGG / OPUS / WMA / 保持原格式 (音频)；采样率、比特率、声道；单个或全部导出（视频文件选音频格式 = 提取声音） |
| 保存位置 | 音频存 `Music/K剪音`，视频存 `Movies/K剪音`（系统不收的类型退到 `Download/K剪音`）；导出后可直接播放 / 分享 |
| 后台导出 | 前台服务 + 通知栏进度，可在通知里停止；切走、锁屏不会被杀 |

**和 PC 版的差别**：
- 没有「源文件目录 / 自定义输出目录」，固定存 `Music/K剪音`（手机上拿不到源文件的真实目录）。
- 「保持原格式」遇到视频文件（mp4/mkv/mov…）会按音轨编码换成音频扩展名（aac→m4a、mp3→mp3、opus→opus…），因为「音乐」目录只收音频。
- 键盘快捷键全部换成按钮；PC 版的「大窗预览」换成全屏画面。
- 逐帧按视频真实帧率（PC 版固定 0.04 秒）。
- 没有声音的视频：PC 版用 ffmpeg 的 anullsrc 生成静音，这里直接写静音 WAV（手机上的 ffmpeg 没编 lavfi 设备）。

## 关键实现

| 文件 | 作用 |
|---|---|
| `core/EditState.kt` | 非破坏性编辑模型，PC 版 `Edit.cs` 一比一移植 |
| `core/Ffmpeg.kt` | 调用内置 ffmpeg（参数用列表传，不经 shell）、解析进度和音视频流、拼导出滤镜（同 PC 版 `BuildFilter`，含视频）、取视频画面（`grabFrame`，BMP 走管道）、时间格式 |
| `core/Pcm.kt` | 读 WAV 波形峰值；`EditReader` 按剪辑结果实时混音；`PcmPlayer` 用 AudioTrack 试听 |
| `core/Formats.kt` | 格式表、「保持原格式」的扩展名规则、MediaStore MIME |
| `Studio.kt` | 全局状态和操作（对应 PC 版 MainForm 的逻辑）：导入、解码、编辑、试听、批量导出、存 MediaStore |
| `WaveModel.kt` + `ui/WaveCanvas.kt` | 波形状态 + 绘制和触摸手势（对应 PC 版 `WaveView.cs`） |
| `ExportService.kt` | 导出前台服务（dataSync），通知栏进度 / 停止 |
| `ui/App.kt` | 全部界面：文件条、波形卡、选区与效果、导出格式、导出结果、日志、底部导出栏 |

**ffmpeg 怎么带进 App**：`ffmpeg-android/build.sh` 在 CI 里用 NDK 交叉编译 ffmpeg 7.1.1（arm64，带 LAME / Vorbis / Opus，
0.3.0 起加 x264 / x265，因此是 GPL；x265 用 venv 里装的 CMake 3.x 编、NEON 汇编编不过会自动退回纯 C；编完检查只依赖系统库），
产物改名 `libffmpeg.so` 放进 `jniLibs/arm64-v8a`。`useLegacyPackaging = true` 让安装时解压到 `nativeLibraryDir`，
那里的文件系统允许执行（App 私有目录不行）。`build.sh` 不变时 CI 直接用缓存（ffmpeg 单独一个 job）。

**处理流程**：导入时把文件复制到 `cache/in/<id>/`（ffmpeg 只认真实路径）并探测时长和音轨 →
选中时解码成 44.1kHz/16bit 立体声临时 WAV（波形 + 试听都用它）→ 导出时 ffmpeg 直接读副本，写到 `cache/out/`，再拷进 MediaStore。
每次冷启动清空 `cache/in`、`cache/out`、试听临时文件（列表不跨启动保留，同 PC 版）。

## 构建

本地没装 Android SDK，push 到 `main` 后由 GitHub Actions 编译（第一次连 ffmpeg 约 15 分钟，之后 3~4 分钟）：

```bash
export HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897
gh run list -R shawnbugs/k-audio -L 3
gh run watch <run_id> -R shawnbugs/k-audio
gh run download <run_id> -R shawnbugs/k-audio -n KAudio-<版本> -D /d/AiWork/Android/k-audio-app/apk
```

- Actions 用不了时在本地 WSL（Ubuntu 24.04）打包：`tools/wsl-root-packages.sh`（root）→ `tools/wsl-setup.sh` → `tools/wsl-build.sh`，
  APK 直接出到 `apk\KAudio-<版本>.apk`，细节见 [交接文档](docs/HANDOFF.md) §4「本地打包」。
- 只出正式版（assembleRelease），固定签名 `app/debug.keystore`（本 App 独立生成），新包直接覆盖安装。
- 只支持 arm64 手机，Android 10 及以上。
